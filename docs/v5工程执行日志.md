## 0. 接手协议（新 session 第一件事读这节）

> 设计目标：每个 session 无状态，靠本节 + 项目入口恢复全部状态，不靠对话记忆。

### 接手 checklist（新 session 第一件事）

1. 读 `CLAUDE.md`（切 v5 目录自动加载，环境/内存红线/结构）+ `PROJECT.md`（项目当前状态）+ `FILE_STRUCTURE.md`（文件/timer 索引）-> 恢复项目背景
2. 读 MEMORY.md（自动）-> 发现 v5 工程进行中
3. 读 `session-state` 最新 memory -> 当前阶段一句话
4. 读本日志第 2 节进度看板 -> 每项状态、哪项"进行中"卡在哪
5. 读本日志第 4 节变更日志最后一条 + 第 5 节待复核清单
6. 读本日志第 6 节文件锁状态 -> 哪个文件有人在改（别撞车）
7. `git log --oneline -5` + `git status` -> 代码到哪、有无未提交
8. 动手前先和老板对齐："我接手，下一步做 X，对吗？"确认再动

### 收尾 checklist（每轮 session 结束前必做）

1. 进度看板更新（进行中 -> 已实现/待复核）
2. 变更日志加一条（日期 + 改了什么文件 + 为什么 + 影响 + 重跑对比基线）
3. 待复核清单更新（哪些结论因此失效）
4. **写"下一步具体动作"**（下轮接手第一件事，具体到文件/行/函数，不是"继续 #8"）
5. 更新 session-state memory（一句话进度 + 指向本日志）
6. `git commit -m "..."`（commit message 写清做了什么）

### 决策冻结规则

- 关键决策记在第 7 节"关键决策记录"（决策 + 依据 + 拍板人 + 日期）
- 新 session 看到能理解为什么这么定，**不重新讨论，只执行**
- 要推翻旧决策必须显式："推翻决策 X，理由 Y"，记进日志，老板确认

### 文件认领（防 glm/ds 撞车）

- 第 6 节"文件锁状态"记录谁在改哪个文件
- 开始改某项前，先在第 6 节标注"glm/ds 认领 #X，进行中"
- 改完划掉。另一脑看到认领就不碰同一文件

### commit/push 节点规则

- **commit 粒度**：每个执行项（#1-#12）完成后 commit 一次，message 写清"做了哪个执行项 + 改了什么 + 为什么"。方便回滚和追溯
- **push 节点**：每项 commit 后立即 `git push`（origin = github.com/spectuam/v5.git，远程备份防本地丢失，数据丢失教训）
- **代码+文档一起 commit**：执行项常涉及代码（.py）+ 文档（工程日志/设计文档），同一 commit 提交保持一致
- **启动前必做**：工程启动第一天，先 commit + push 现有文档基建（工程日志、综合讨论、因子动量v2、PROJECT.md 更新），作"文档基线"存到 GitHub，防本地丢失
- **commit message 模板**：`[#X] 事项简述：改了什么/为什么`，如 `[#8] FDR 接入：后处理脚本写 fdr_pass + daily_pick 加载逻辑加检查`
- **同步更新的文档**：收尾 checklist 第 1-5 条（进度看板/变更日志/待复核/下一步动作/session-state）是每步必更，缺一不可
