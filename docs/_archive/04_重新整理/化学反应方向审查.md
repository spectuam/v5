## 3. 反复劝退模式

化学反应 / 非线性 / 状态切换被"天花板 / 数据量不足"反复劝退：
- state_switch（7/22）凭"三轮 0.50-0.53"判定"状态切换也不解决"，转向改评估标准
- fable5（7/23-27）判"非线性交互数据量不足以支撑"
- 工程（7/28）走线性因子动量

**week 发现证明：至少"因子动量信号弱"那次劝退是口径混淆误判。** 所以之前那些"做不了"的判断值得重审一次。

**诚实限定**：fable5 的"公开因子库 alpha 已终结""38 因子库太小"是数据/规模硬约束，不是口径问题，不会因分层消失。结论不是"化学反应一定能成"，是**"从未被干净试过一次"**--每次都被错配（qlib 用公开因子池+格式bug）或口径混淆（week 被成本埋、state_switch 凭印象转向）绊倒，没到真正检验就退了。

## 4. 方向（老板确认，已修正）

**目标不是判断化学反应存不存在，是把"历遍筛选组合方式、选出更好策略"的方法本身内化进架构。** 化学反应测试只是验证这个方法管不管用的场子。无论结论如何，这个历遍 + 选优能力都该做成系统能力。

测试条件：
- **用 v5 的 38 正交因子**（低维，数据量够，过拟合可控）--不是 Alpha158
- **条件激活方向**（三层递进 Layer3 / state_switch Phase0 思路），不急着上黑箱 ML
- **week 颗粒度**（诊断层信号强）
- **诊断层口径干净**（只问交互存不存在，不让成本/实盘提前介入）
