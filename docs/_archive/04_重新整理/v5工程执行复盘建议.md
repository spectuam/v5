## 5. SOP 编排脚本（`sop_pipeline.py`）

**现状**：SOP 各步脚本（diagnose / decile / long_ic / fdr / phase2_stock / pbo_dsr / guard_fm1 等）都是独立 `.py` 文件，分布在不同目录下。新因子加入后每步需手动逐个运行，没有总控串联。

**建议**：写一个 `sop_pipeline.py`，把 SOP 路径 1-7 步串成一条命令跑完：

```
sop_pipeline.py [--factor <name>] [--skip <steps>]
```

**编排逻辑**：
1. #5 诊断层（diagnose.py）→ 输出诊断报告
2. **决策门 A 暂停**：打印报告摘要（AR(1)占比、转移矩阵 CI），等人工输入 `y/n`，n → 归档退出
3. #3 Decile + #4 多头 IC → 因子用法标注
4. #7 NW / #8 FDR / #9 成本 → 校准（如已跑过可跳过）
5. #11 2.2 选股级回测 → 输出训练/OOS 夏普
6. **暂停确认**：训练正 + OOS 正？打印摘要等人确认
7. #11 2.4 block bootstrap + 2.5 CPCV + 2.6 护栏
8. **决策门 B 暂停**：PBO/DSR/护栏/显著性汇总，等人工输入 `y/n`
9. （若通过）成本复核 → 最终报告

**核心价值**：
- 新因子引入从"手动 7 步"变成"一条命令 + 3 次人工判断"
- 减少漏步（不会忘了跑 block bootstrap 或 CPCV）
- 中间产物自动存档（`pipeline_runs/<factor>_<date>/` 下留完整结果）
- 决策门仍由人判断（不搞全自动），编排只解决"串起来 + 不漏步"

**理由**：SOP 固化了流程，但执行还是手动的。编排脚本把"流程知识"变成"可执行命令"，降低新因子引入的操作门槛和出错率。

## 6. 因子动量周颗粒验证实验

**问题**：当前全链路基于月度 IC。但公开因子衰减快，月颗粒可能已把信号抹平。AR(1) 75.7% 显著低于 GK 91%、转移矩阵 lift 仅 1.41、选股级训练负，这些都可能不是"没信号"，而是"量尺太粗"。

**假设**：因子动量如果在 A 股还有效，信号窗口应该在周级别。

**建议**：不做全链路重跑，只做最小验证。

**最小验证方案**：
1. 改 factor_map IC 计算：月度 → 周度（一段代码）
2. 重跑 `diagnose.py`（秒级），只看两个数：

| 指标 | 月颗粒（当前） | 周颗粒（若改善） |
|------|--------------|-----------------|
| AR(1)>0 占比 | 75.7% | 应接近 GK 91% |
| 转移矩阵 lift | 1.41 | 应 > 1.41 |

3. 判定：
   - 两个数明显改善 → "周颗粒可行"，铺开重跑全链路
   - 差不多或更弱 → "不是颗粒度问题"，因子动量在中国 A 股信号弱，关门

**附**：切换周颗粒后数据点显著增加，回测周期可相应缩短（如 5 年 ~250 周，MinTRL 有效 block >10 即可），不需要拉满 10 年。

**工作量**：半天（改 IC 计算 + 跑 diagnose + 对比）。
